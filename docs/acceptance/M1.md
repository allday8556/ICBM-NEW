### Protected-read negative control (Issue #7 comment 5653567880)

The proof target is P = `/myshop/index.html` (마이쇼핑). Every proof reads the **same P** twice.

| Request to P | Transport | HTTP status | Classification | Marker names observed |
| --- | --- | --- | --- | --- |
| Without any session (`CONTROL_READ`) | HTTP | **200** | **LOGIN_REQUIRED** | `state_logoff`, `login_check_redirect` |
| With the authenticated session (`PROTECTED_READ`) | HTTP | 200 | **AUTHENTICATED** | `state_logon`, `logout_action`, plus the informational `member_modify_link` |

What this shows:

- **HTTP 200 is not the proof.** The unauthenticated request is answered with 200, and the `xans-myshop` page skeleton is present even then.
- **The verdict comes from the server-rendered markers.** Without a session the logged-off module and the login-check redirect are present. With the session the logged-on module and the member logout action are present together.
- **The target is genuinely authentication-gated.** The same P, read without and with the session, falls on opposite sides of the proof. That held in every one of the 4 proofs of this run.
- **The first real login confirmed the ADR-0007 predicate hypothesis.** Its markers were a hypothesis based on the Cafe24 convention; the logged-in page shows the logged-on module together with the logout action.
- **Only marker names were recorded.** No page content was stored.

### Secret scan (counts only, five encodings)

What was scanned:

- **Artifacts:** the acceptance data directory (`icbm.db` with its WAL/SHM files, `logs/**`, `sessions/*.enc`) and the acceptance output directory (`evidence.json` and three server logs) — **11 files** in total.
- **Secrets:**
  - the ID and password, read in memory from the OS secret store;
  - every cookie value of the final authenticated session, decrypted in memory, where the value has at least 6 characters. Shorter values are flags too short to identify a session, so the scan skips them to avoid false positives.
- **Encodings:** raw text (UTF-8, UTF-16-LE, CP949), URL encoding, JSON escaping, Base64 (standard and URL-safe, at every byte alignment) and HTML entities.

| `username` | 0 | 0 | 0 | 0 | 0 |
| `password` | 0 | 0 | 0 | 0 | 0 |
| `cookie:ECSESSID` | 0 | 0 | 0 | 0 | 0 |
| `cookie:PHPSESSVERIFY` | 0 | 0 | 0 | 0 | 0 |
| `cookie:login_provider_1` | 0 | 0 | 0 | 0 | 0 |
| `cookie:wish_id` | 0 | 0 | 0 | 0 | 0 |
| `cookie:fb_external_id` | 0 | 0 | 0 | 0 | 0 |
